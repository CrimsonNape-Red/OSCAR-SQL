# Notes Reorganization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sort `Notes/` into subject folders, move user-facing material to `UserResources/`,
and set up the private `DevPrivate` folder, with every reference still valid.

**Architecture:** One tab-separated map lists every tracked file under `Notes/` with its new
path. A move step applies the map with `git mv`; a second step rewrites every mention of an old
path, byte for byte, in tracked text files. The moves and the reference fixes are separate
commits so history follows each file.

**Tech Stack:** git, Python 3 for the two helper scripts, the `build-oscar` skill for the
compile check.

**Spec:** `Notes/specs/2026-11-21-notes-reorganization-design.md`

**Map:** `Notes/specs/2026-11-22-notes-reorganization-map.tsv` (columns: action, old path, new
path), generated by `2026-11-22-notes-reorganization-make-map.py` beside it.

## Global Constraints

- No change to program behaviour. Edits under `oscar/` are comment-only.
- Never touch `oscar/SleepLib/thirdparty`.
- Note content is not rewritten, apart from the paths it cites.
- No anonymizer, checksum algorithm or tester-identifying detail goes into the repository.
- `Tools/` stays flat and in place; `oscar/oscar.pro` calls `Tools/gen_system_report_strings.py`.
- Nothing is committed or pushed without the lead developer's say-so. Commit messages are
  written to a file and committed with `git commit -F`; lines at most 90 characters; no
  co-author line.
- No paid service.

## Review Focus

1. **Case-sensitive file systems.** Linux distinguishes `Notes/database` from
   `Notes/Database`. Every rewritten path must match the new folder's exact case. Checked in
   Task 3, step 4.
2. **Paths written another way.** Backslashes (`Notes\loaders\...`) and URL-encoded spaces
   (`Developer%20Notes`) must be rewritten too. Checked in Task 3, step 3.
3. **Scripts that find files by their own location.** Three moved scripts hold path strings
   that are already stale. Fixed in Task 3, step 5.
4. **Accidental content change.** A move must be a pure rename, and a reference fix must not
   change line endings or encoding. Checked in Task 2, step 4 and Task 3, step 6.
5. **Things outside the repository.** Each developer's `AGENTS.md`, the local `shipfix` skill,
   Claude's memory files and the other worktrees cite old paths. Handled in Task 4. Links from
   GitLab issues and forum posts into `Notes/` on master will break; the design accepts that.

### Task 1: Helper scripts and baseline

**Files:**
- Create: `<scratchpad>/reorg/apply_refs.py`
- Create: `<scratchpad>/reorg/baseline.txt`

**Interfaces:**
- Consumes: the map file (action, old path, new path; tab-separated, UTF-8).
- Produces: `apply_refs.py <repo> <map.tsv> [--write]`. Without `--write` it only reports. It
  prints one line per hit as `file:line: old -> new` and ends with `hits: N`. Exit code 0.

- [ ] **Step 1: Write `apply_refs.py`.** For every file from `git ls-files`, skipping
  `oscar/SleepLib/thirdparty/`, binary files and the map file itself: read as bytes, and for
  each `move` row replace the old path with the new one, longest old path first. Match three
  spellings of each old path: forward slashes, backslashes (replace with the new path in
  backslashes), and URL-encoded spaces (`%20`, replace with the new path encoded the same way).
  Write back only with `--write`, and only if the bytes changed.
- [ ] **Step 2: Record the baseline.** Run `python apply_refs.py . <map>` and save the output to
  `baseline.txt`. Expected: `hits:` is above 100 (a plain search found about 210 mentions of
  `Notes/`, `Tools/` or `history/` across 78 files).
- [ ] **Step 3: Record the file count.** Run `git ls-files Notes Tools UserResources | wc -l`.
  Expected: 239.
